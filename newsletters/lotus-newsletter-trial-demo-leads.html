You've been exploring Document360 to build a knowledge base your users can rely on.

If your developers already keep docs in a GitHub repo, you've probably hit the same wall as everyone else.

  Two copies of every doc: Markdown in the repo, a pasted copy in the help center, and they never match for long.

That's why we built Document360 Lotus, docs as code built into Document360.

Your docs live in GitHub and stay in sync with Document360 in both directions, so everyone works on the same docs in the tool they already use.

What you get

One source of truth, two ways to edit it

Two-way GitHub sync

Commit in GitHub or edit in Document360. Every change lands on both sides.

Git in the browser

Branch, save, open a pull request and Merge & publish from the editor.

Conflicts made simple

See both versions side by side and keep GitHub's, yours, or both.

Agent-ready setup

Your coding agent writes the d360.json manifest from a prompt we provide.

How it works

From your repo to a live knowledge base in four steps
1

Choose Lotus

Start a new project and pick Document360 Lotus, the docs-as-code project type.
2

Connect GitHub

Authorize GitHub, install the app, and pick any repository and branch.

Docs in a subfolder work too.
3

Add the manifest

Lotus maps folders to categories with a small d360.json file.

Don't have one? Paste our prompt into Claude Code, Cursor or Codex, or start from a template.
4

Sync and keep working

Developers keep committing, writers keep editing, and Lotus syncs both ways.

The momentDocs as code todayWith Lotus
