## Post for community.document360.com

> **Coming soon: Document360 Lotus (Beta), docs as code with two-way GitHub sync**
>
> Hi everyone,
>
> Many of you asked for this one. Today our GitHub extension syncs one way, from the main branch into Document360. Document360 Lotus is a new project type that syncs both ways.
>
> With Lotus, your docs live in a GitHub repository and stay in sync with Document360 in both directions:
>
> - Developers commit Markdown to any branch. Writers and PMs edit in the Document360 editor. Every change lands on both sides.
> - Create branches, save commits, open pull requests and **Merge & publish** without leaving Document360.
> - When GitHub and Document360 both change an article, resolve it in the browser: keep GitHub's version, yours, or both.
> - Missing a `d360.json` manifest? Paste our prompt into your coding agent and it builds one for you.
> - Writers don't need a GitHub account: what they can do follows their Document360 role.
> - Publish every change in one reviewed commit. If main is protected, Lotus opens a pull request instead.
>
> We're opening early access to a small group, and community members are first in line: [Join the waitlist](https://document360v2.wpengine.com/lotus-waitlist-2/?utm_source=community&utm_medium=post&utm_campaign=lotus_waitlist)
>
> One question for you: where do your docs live today, in a repo, in Document360, or both? Reply below. Your answers will shape our migration guides.
